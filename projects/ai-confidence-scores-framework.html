The Overconfidence Problem in Production LLMs

When deploying modern Large Language Models (LLMs) such as Gemini 2.5 Flash to automate unstructured document processing, one issue repeatedly surfaces: raw probability outputs from instruction-tuned models are severely uncalibrated. Post-training reinforcement learning (RLHF/RLAIF) aligns models to generate fluent, decisive completions, but it systematically squashes predicted token log probabilities toward 1.0 or 0.0. As a result, a raw model confidence score of 0.98 does not mean the model is right 98% of the time.

In high-stakes enterprise applications, such as candidate resume parsing and recruiter routing, uncalibrated overconfidence creates hidden failure modes. An erroneous domain classification (for instance, classifying a Financial Analyst as a Data Scientist) might pass through automated hiring workflows without triggering a human review. Conversely, setting an arbitrary fixed threshold on uncalibrated probabilities leads to either auditing too many correct extractions or letting critical errors slide.

To address this challenge, I built ai-confidence-scores, an enterprise-grade evaluation and calibration framework using Google's modern google-genai SDK. I implemented, benchmarked, and comparative-evaluated 10 distinct confidence scoring methods across multimodal PDF resumes. My objective was to determine which calibration frameworks deliver true statistical accuracy while minimizing runtime latency and API overhead.

Official Reference Documentation: For foundational concepts on token log probabilities in Gemini, explore the official Gemini Logprobs Tutorial Notebook and the Gemini GenerationConfig API Reference.

Preferred Method for Gemini 3.0+ Models: Starting with Gemini 3.0 and greater (including Gemini 3.0 Flash, Gemini 3.5, and Gemini 3.6 Flash/Pro), token logprobabilities (response_logprobs) are unavailable or disabled in generation parameters. The Structured Self-Assessment + Platt Scaling Method (StructuredSelfAssessmentPlattMethod) is specifically engineered as the preferred, flagship calibration solution for Gemini 3.0+. By combining structured self-assessment (categorical and continuous confidence ratings) with post-hoc logistic Platt scaling, it delivers mathematically rigorous, logprob-independent confidence calibration for modern production pipelines.

The Dataset & Ingestion Pipeline

Evaluating confidence calibration requires a realistic dataset with complex, multi-page formatting and inherent domain ambiguity. For this benchmark, I used synthetic PDF candidate resumes. Synthetic resumes mirror real-world applicant data: non-standard job titles, multi-column visual layouts, mixed technical keywords, and varying experience lengths across multiple career transitions.

To ingest these documents, I built a dual parsing pipeline in src/ingestion.py that provides two complementary input paths for Gemini 2.5 Flash:

  • Layout-Preserved PyMuPDF Text Extraction: Extracts structural text blocks using pymupdf (fitz), injecting page demarcation tags (--- Page N ---) for zero-latency CPU text processing.
  • Direct Native Multimodal PDF Ingestion: Reads raw PDF bytes into types.Part.from_bytes(data=pdf_bytes, mime_type="application/pdf"). This passes raw visual document bytes straight to Gemini's vision engine, bypassing text parsing errors caused by complex multi-column grids or custom fonts.
from pathlib import Path
from typing import Tuple, Union
import pymupdf as fitz

class ResumeIngestor:
    """Handles scanning, loading, and text layout extraction for PDF resumes."""

    def __init__(self, data_directory: Union[str, Path] = "./data"):
        self.data_directory = Path(data_directory)

    @staticmethod
    def extract_text_pymupdf(pdf_path: Union[str, Path]) -> str:
        """Extract layout-preserved text from PDF using PyMuPDF."""
        extracted_text = []
        with fitz.open(pdf_path) as doc:
            for page_num, page in enumerate(doc):
                text = page.get_text("text")
                if text.strip():
                    extracted_text.append(f"--- Page {page_num + 1} ---\n{text}")
        return "\n\n".join(extracted_text).strip()

    @staticmethod
    def load_pdf_bytes(pdf_path: Union[str, Path]) -> bytes:
        """Load raw PDF bytes for native Gemini multimodal ingestion."""
        return Path(pdf_path).read_bytes()

Pydantic Contracts and Flexible Domain Schemas

A core design choice of this framework is strict schema enforcement. By leveraging Pydantic, all extractions are guaranteed to conform to structural contracts. The core benchmark targets ResumeExtraction, which categorizes candidates into domain roles and seniority tiers while capturing atomic factual claims for factual verification.

Handling unstructured LLM outputs requires robust enum validation. I implemented custom _missing_ classmethods on domain enums to map messy LLM string returns (such as "Machine Learning Engineer" or "AI Researcher") directly to canonical enum values (such as DomainRole.DATA_SCIENCE).

from enum import Enum
from typing import List, Optional
from pydantic import BaseModel, Field

class DomainRole(str, Enum):
    SOFTWARE_ENGINEERING = "Software Engineering"
    DATA_SCIENCE = "Data Science"
    FINANCE = "Finance"
    HUMAN_RESOURCES = "HR"
    BUSINESS_DEVELOPMENT = "Business Development"
    OTHER = "Other"

    @classmethod
    def _missing_(cls, value: object) -> "DomainRole":
        if isinstance(value, str):
            val_lower = value.lower()
            if any(k in val_lower for k in ["data", "machine learning", "ai", "analytics"]):
                return cls.DATA_SCIENCE
            if any(k in val_lower for k in ["software", "engineer", "developer"]):
                return cls.SOFTWARE_ENGINEERING
            if any(k in val_lower for k in ["finance", "accounting", "financial"]):
                return cls.FINANCE
            if any(k in val_lower for k in ["hr", "human", "recruitment", "talent"]):
                return cls.HUMAN_RESOURCES
            if any(k in val_lower for k in ["business", "sales", "marketing"]):
                return cls.BUSINESS_DEVELOPMENT
        return cls.OTHER

class ResumeExtraction(BaseModel):
    """Specialized extraction schema for PDF Resume classification benchmark."""
    candidate_name: str = Field(default="Unknown Candidate", description="Full candidate name")
    domain_role: DomainRole = Field(default=DomainRole.OTHER, description="Classified professional domain role")
    seniority_level: str = Field(default="Other", description="Extracted candidate seniority level")
    years_of_experience: float = Field(default=0.0, description="Estimated total years of professional experience")
    key_skills: List[str] = Field(default_factory=list, description="Top technical and professional skills")
    key_claims: List[str] = Field(default_factory=list, description="Atomic factual claims extracted from resume")

class CalibrationResult(BaseModel):
    method_name: str
    extraction: ResumeExtraction
    raw_confidence: float
    calibrated_confidence: float
    audit_decision: str  # "AUTOMATE" vs "FLAG_FOR_HUMAN_REVIEW"
    latency_ms: float
    metadata: dict

Mathematical Breakdown & Architectural Implementation of the Calibration Methods

I structured the calibration suite around specialized calibration methods, spanning token-level statistics, post-hoc statistical modeling, sampling agreement, verbalized self-assessment, and context alignment verification.

Method 1: Native Token LogProb Method (NativeLogProbMethod)

This method requests token log probabilities directly from Gemini 2.5 Flash by configuring response_logprobs=True and logprobs=5 in types.GenerateContentConfig. It computes the raw joint sequence confidence as the exponentiated geometric mean of all output token log probabilities:

$$\text{Confidence}_{\text{native}} = \exp\left( \frac{1}{N} \sum_{i=1}^N \text{logprob}_i \right)$$

Simple Explanation: Think of this like taking the average grade the AI gives itself for every single word it generates. If the AI feels confident about every word in its answer, the overall score stays high.

Practical Example: Useful as a fast, lightweight baseline check in high-throughput text pipelines when you want a quick raw measurement of output stability without setting up external post-processing tools.

from google.genai import types
import math

# Method 1: Native Token LogProb Method (Sequence Geometric Mean)
config = types.GenerateContentConfig(
    response_mime_type="application/json",
    response_schema=ResumeExtraction,
    response_logprobs=True,
    logprobs=5,
    temperature=0.0,
)

response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents=[prompt],
    config=config
)

# Extract chosen candidate log probabilities
logprob_values = [cand.log_probability for cand in response.candidates[0].logprobs_result.chosen_candidates]
mean_logprob = sum(logprob_values) / len(logprob_values)
confidence = math.exp(mean_logprob)  # Geometric mean sequence confidence

Method 2: LogProb Delta Method (LogProbDeltaMethod)

Because full sequence joint log probabilities suffer from length penalty decay and saturation, Method 2 measures the top-token dominance margin. For each generated token, it computes the log-probability margin between the selected top token (\(\text{logprob}_{\text{top\_1}}\)) and the runner-up token (\(\text{logprob}_{\text{top\_2}}\)):

$$\Delta = \text{logprob}_{\text{top\_1}} - \text{logprob}_{\text{top\_2}}$$ $$\text{Confidence}_{\text{delta}} = \sigma(\bar{\Delta}) = \frac{1}{1 + e^{-\bar{\Delta}}}$$

If the model is certain of its choice, \(\Delta\) is large. If an alternative candidate token is close in likelihood, \(\Delta\) collapses toward 0, indicating classification hesitation.

Simple Explanation: Imagine asking someone to pick between Option A and Option B. If Option A is a clear winner and Option B is nowhere close, their confidence gap (delta) is huge. But if Option A and B are almost tied, they hesitate. This method measures that exact margin between the AI's top choice and its runner-up.

Practical Example: Perfect for automated candidate resume screening where applicants list hybrid job titles (such as "Financial Data Analyst"). If the AI hesitates between classifying them under "Finance" vs "Data Science", the confidence margin shrinks instantly, flagging the resume for recruiter review.

# Method 2: LogProb Delta Method (Top-2 Token Dominance Margin)
deltas = []
top_cands_list = response.candidates[0].logprobs_result.top_candidates

for top_cand_group in top_cands_list:
    cands = top_cand_group.candidates
    if len(cands) >= 2:
        p1 = cands[0].log_probability  # Top candidate token probability
        p2 = cands[1].log_probability  # Runner-up alternative token probability
        deltas.append(abs(p1 - p2))

mean_delta = sum(deltas) / len(deltas)
confidence = 1.0 / (1.0 + math.exp(-mean_delta))  # Logistic sigmoid of mean delta margin

Method 3: Post-Hoc Temperature Scaling Method (TemperatureScalingMethod)

Temperature scaling applies a single learned parameter \(T > 1\) to smooth output token logits \(z_i\) post-hoc, optimizing Negative Log-Likelihood (NLL) on a holdout calibration set without altering classification argmax predictions:

$$P_{\text{calibrated}}(i) = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

Simple Explanation: Imagine an overly enthusiastic teacher who gives almost every student an A+. Temperature scaling is like applying a gentle curve to the test scores after grading, cooling down overly optimistic estimates without changing who actually placed first.

Practical Example: Ideal when you have a small dataset of human-verified resumes and need a fast global adjustment to temper overconfident predictions across all job categories without training a complex machine learning model.

# Method 3: Post-Hoc Temperature Scaling Method
raw_logit = sum(logprob_values) / len(logprob_values)  # Mean output logprob

# Apply temperature scaling (un-fitted default T = 1.2 or NLL-fitted T*)
scaled_logit = raw_logit / max(self.temperature, 0.01)
calibrated_confidence = math.exp(scaled_logit)  # Temperature-scaled confidence

Method 4: Platt Scaling Logistic Method (PlattScalingMethod)

Platt Scaling fits a 1D logistic regression model mapping the empirical token delta \(\bar{\Delta}\) (or sequence logprob) directly to true empirical correctness on a validation fold:

$$P(y=1 \mid \bar{\Delta}) = \frac{1}{1 + \exp(A \cdot \bar{\Delta} + B)}$$

This transforms raw margin statistics into true calibrated empirical probabilities, correcting for global model overconfidence bias.

Simple Explanation: This method compares the AI's internal certainty against a historical report card. It trains a statistical model that learns, for example: "Whenever the AI exhibits a token delta margin of 3.0, it is historically accurate 92% of the time." It converts raw AI signals into real-world historical probabilities.

Practical Example: The gold standard for enterprise production hiring portals. If an automated system must process 50,000 applicant resumes per day under a strict 95% precision SLA, Platt Scaling maps raw model logprobs into calibrated real-world probabilities in under 4 milliseconds.

from sklearn.linear_model import LogisticRegression
import numpy as np

class PlattScalingMethod(BaseConfidenceMethod):
    """Method 4: Platt Scaling Logistic Method."""

    def __init__(self, **kwargs):
        super().__init__(**kwargs)
        self.platt_model = LogisticRegression()
        self.is_fitted = False

    def fit(self, val_deltas: np.ndarray, val_correctness: np.ndarray) -> None:
        """Fit 1D Logistic Regression mapping logprob deltas to empirical correctness."""
        X = val_deltas.reshape(-1, 1)
        y = val_correctness.astype(int)
        self.platt_model.fit(X, y)
        self.is_fitted = True

    def evaluate(self, input_text: str, **kwargs) -> CalibrationResult:
        # 1. Fetch response with logprobs=5
        # 2. Compute mean token delta \bar{\Delta}
        # 3. Apply fitted Platt logistic model:
        if self.is_fitted:
            calibrated_conf = self.platt_model.predict_proba(np.array([[mean_delta]]))[0, 1]
        else:
            # Unfitted default fallback sigmoid curve
            calibrated_conf = 1.0 / (1.0 + np.exp(-(1.2 * mean_delta - 0.5)))
        return CalibrationResult(...)

The Two-Phase Architecture of Temperature & Platt Scaling

Both TemperatureScalingMethod and PlattScalingMethod are designed with a two-phase architecture: they work out-of-the-box using heuristic baseline priors when no golden dataset is available, and transition to statistically optimal fitted parameters once a validation dataset is provided.

1. Un-Fitted Mode (Zero-Shot / No Golden Dataset)

When you instantiate these methods without calling .fit(), is_fitted is False. The methods apply theoretical baseline parameters so you can evaluate confidence immediately:

  • Temperature Scaling Method (TemperatureScalingMethod):
    Mechanism: Extracts the mean token log-probability (\(\bar{\log P} = \frac{1}{N}\sum \log P(t_i)\)).
    Default Prior: Uses an initial temperature parameter \(T = 1.2\) (temperature_scaling.py:L30). $$\text{Logit}_{\text{scaled}} = \frac{\bar{\log P}}{\max(T, 0.01)}$$ $$\text{Calibrated Confidence} = \exp(\text{Logit}_{\text{scaled}})$$ Effect: Since LLMs are notoriously overconfident (\(T > 1\)), scaling down the logit by \(T = 1.2\) softens raw probabilities slightly downward toward realistic expectations.
  • Platt Scaling Method (PlattScalingMethod):
    Mechanism: Computes the mean margin/delta between top token choice (\(p_1\)) and runner-up alternative (\(p_2\)): \(\bar{\Delta} = \frac{1}{N}\sum |p_1 - p_2|\).
    Default Prior: Applies a standard logistic sigmoid prior with slope \(A = 1.2\) and intercept \(B = -0.5\) (platt_scaling.py:L158): $$\text{Calibrated Confidence} = \sigma(1.2 \cdot \bar{\Delta} - 0.5) = \frac{1}{1 + e^{-(1.2 \bar{\Delta} - 0.5)}}$$ Effect: Maps the raw logprob margin \(\bar{\Delta}\) onto a \([0.0, 1.0]\) probability curve without requiring prior training data.

2. Fitted Mode (With Labeled / Golden Dataset)

When you provide a labeled validation set (\(y_i \in \{0, 1\}\) representing empirical extraction correctness), calling .fit() optimizes the parameters specifically for your domain data:

  • Fitting Temperature Scaling (method.fit(val_logits, val_labels)):
    Accepts a set of validation logits (\(\bar{\log P}_i\)) and binary correctness labels (\(y_i \in \{0, 1\}\)). Uses scipy.optimize.minimize (temperature_scaling.py:L58) to find the exact temperature \(T^*\) that minimizes Negative Log-Likelihood (NLL) loss: $$\mathcal{L}(T) = -\frac{1}{M}\sum_{i=1}^M \left[ y_i \log \sigma\left(\frac{\text{logit}_i}{T}\right) + (1 - y_i) \log\left(1 - \sigma\left(\frac{\text{logit}_i}{T}\right)\right) \right]$$ Sets is_fitted = True. All subsequent evaluations scale logits by \(T^*\).
  • Fitting Platt Scaling (method.fit(val_deltas, val_correctness)):
    Accepts validation logprob deltas (\(\bar{\Delta}_i\)) and ground-truth correctness labels (\(y_i \in \{0, 1\}\)). Trains a sklearn.linear_model.LogisticRegression model (platt_scaling.py:L51) to learn optimal slope \(A^*\) and intercept \(B^*\): $$P(Y=1 \mid \bar{\Delta}) = \frac{1}{1 + e^{-(A^* \bar{\Delta} + B^*)}}$$ Sets is_fitted = True. All subsequent evaluations predict probabilities using platt_model.predict_proba([[mean_delta]]).

Method 5: Self-Consistency & Sampling Agreement Method (SelfConsistencyMethod)

Method 5 runs \(N=5\) stochastic completions in parallel at a higher sampling temperature (\(T=0.7\)). It clusters the structured JSON outputs by primary field matches and returns the majority cluster ratio as the confidence estimate:

$$\text{Confidence}_{\text{self-consistency}} = \frac{\text{Majority Cluster Size}}{N}$$

Simple Explanation: Think of asking 5 independent human experts the same question. If all 5 give the exact same answer, you can be extremely confident. If 3 experts say one thing and 2 say another, there is room for doubt. This method measures how often multiple independent AI runs agree with one another.

Practical Example: Excellent for parsing senior executive resumes with ambiguous career histories. When low-level token probabilities are unavailable or restricted by an API endpoint, generating 5 parallel extractions and checking for majority consensus provides a strong reliability metric.

from collections import Counter

# Method 5: Self-Consistency Method (N=5 Parallel Completions at T=0.7)
sample_extractions = []
config = types.GenerateContentConfig(
    response_mime_type="application/json",
    response_schema=ResumeExtraction,
    temperature=0.7,
)

for _ in range(5):
    resp = client.models.generate_content(model="gemini-2.5-flash", contents=[prompt], config=config)
    sample_extractions.append(ResumeExtraction.model_validate_json(resp.text))

# Cluster extractions by domain role & return majority vote agreement ratio
clusters = Counter([ext.domain_role for ext in sample_extractions])
majority_key, majority_count = clusters.most_common(1)[0]
confidence = majority_count / len(sample_extractions)  # Majority agreement ratio

Method 6: Structured Self-Assessment Method (VerbalizedConfidenceMethod)

Method 6 asks Gemini 2.5 Flash to evaluate its own confidence. Using Pydantic JSON schema enforcement (response_schema=VerbalizedConfidenceOutput), the prompt forces the model to generate a chain-of-thought rationale followed by a verbalized score \(S_{\text{verb}} \in [0.0, 1.0]\).

Simple Explanation: This is like asking a student to explain their thought process step-by-step on an exam, and then write down a percentage score at the bottom showing how sure they feel about their own answer.

Practical Example: Great for internal HR dashboards where recruiters want to read the AI's step-by-step reasoning alongside a self-rated confidence score before deciding whether to invite a candidate to interview.

$$\text{Confidence}_{\text{continuous}} = \frac{R}{100.0}$$

Simple Explanation: Instead of analyzing raw token math or probability curves, this asks the AI directly: "On a scale from 0 to 100, how sure are you about this extraction?" and converts the number into a decimal score.

Method 8: Grounding & Context Alignment Method (GroundingAlignmentMethod)

Method 8 verifies facts using Natural Language Inference (NLI). It parses atomic factual claims from the LLM extraction (for instance, "Candidate managed a $2M budget at Company X") and runs each claim through an NLI verification check against the raw PDF source text:

$$\text{Grounding Score} = \frac{\text{Supported Claims}}{\text{Total Extracted Claims}}$$

Simple Explanation: Imagine a meticulous fact-checker cross-examining every single sentence in a summary against the original document. If the summary claims "Managed a $5M budget" but the original PDF only says "Supported budget tracking", the fact-checker flags the claim as unsupported.

Practical Example: Crucial for compliance-heavy background verification (such as confirming professional certifications, security clearances, or university degrees) to guarantee zero hallucinations before updating HR databases.

# Method 8: Grounding & Context Alignment Method (NLI Verification against Source Text)
claims = extraction.key_claims  # Extracted atomic factual claims

verification_prompt = (
    f"For each claim below, verify if it is strictly SUPPORTED by source text.\n"
    f"Source Text:\n{pdf_text}\n\nClaims: {claims}"
)

config = types.GenerateContentConfig(
    response_mime_type="application/json",
    response_schema=GroundingOutput,
    temperature=0.0,
)

ground_resp = client.models.generate_content(model="gemini-2.5-flash", contents=[verification_prompt], config=config)
grounding_res = GroundingOutput.model_validate_json(ground_resp.text)

supported_count = sum(1 for c in grounding_res.claims if c.verdict == "SUPPORTED")
confidence = supported_count / len(grounding_res.claims)  # NLI Grounding Score

Method 9: Two-Tier Evaluator Method (LLMAsAJudgeMethod)

Method 9 routes extractions to a secondary judge instance of gemini-2.5-flash acting as an auditor. The judge evaluates the candidate extraction against a strict rubric scoring precision, hallucination risk, and completeness on a 1–5 scale, normalizing the overall rubric average to \([0.0, 1.0]\).

Simple Explanation: This uses a second, independent "senior manager" AI to review and grade the work of the first "worker" AI using a detailed rubric scoring completeness, precision, and accuracy from 1 to 5.

Practical Example: Ideal for asynchronous auditing of flagged edge-case extractions. If the primary extraction method is uncertain about a candidate's background, the resume is forwarded to a secondary AI Judge for a full audit before reaching human reviewers.

# Method 9: Two-Tier Evaluator Method (LLM-as-a-Judge Rubric Audit)

Evaluate primary extraction quality against raw source text.

Method 10: Structured Self-Assessment + Platt Scaling Method (StructuredSelfAssessmentPlattMethod)

Logprob-Independent Calibration Strategy for Gemini > 3.0 Models
For newer Gemini models (e.g., Gemini 3.0 Flash, Gemini 3.5, Gemini 3.6 Flash/Pro), token logprobabilities (response_logprobs) are unavailable or disabled. The Structured Self-Assessment + Platt Scaling Method provides a robust, logprob-independent calibration solution.

Method 10 combines structured LLM self-assessment with post-hoc logistic regression calibration in three distinct steps:

  1. Structured Self-Assessment: Prompts Gemini for structured extraction along with step-by-step chain-of-thought rationale, a categorical confidence rating (VERY_LOW, LOW, MEDIUM, HIGH, VERY_HIGH), and a continuous numerical confidence rating in \([0.0, 1.0]\).
  2. Logit Transformation: Converts the raw self-assessment probability \(p_{\text{raw}}\) into unbounded logit space: $$z = \text{logit}(p_{\text{raw}}) = \ln\left(\frac{p_{\text{raw}}}{1 - p_{\text{raw}}}\right)$$
  3. Platt Scaling: Applies logistic calibration scaling fitted on empirical ground-truth validation data via Negative Log-Likelihood (NLL) loss minimization: $$P_{\text{calibrated}} = \sigma(a \cdot z + b) = \frac{1}{1 + e^{-(a \cdot z + b)}}$$

This method includes a .fit(val_scores, val_labels) helper that optimizes slope parameter \(a\) and intercept parameter \(b\) on a validation dataset using scipy.optimize.minimize.

Simple Explanation: Think of taking a student's self-assessed percentage score on a quiz, converting it into a statistical log-odds score, and adjusting it against their historical report card using a logistic curve. It gives you the gold-standard accuracy of Platt Scaling without needing raw word-by-word token probabilities.

Practical Example: The premier choice for production deployments on Gemini 3.0 Flash, Gemini 3.5, and Gemini 3.6 Flash/Pro. Because token logprobs are disabled in Gemini 3.0+, combining structured self-assessment with Platt scaling delivers mathematically optimal, calibrated confidence scores on validation datasets.

import math
import numpy as np
from pydantic import BaseModel, Field
from scipy.optimize import minimize

# Method 10: Structured Self-Assessment + Platt Scaling (Gemini 3.0+ Preferred Method)
class StructuredSelfAssessmentPlattMethod:
    """Logprob-independent calibration combining self-assessment with fitted Platt scaling."""

    def __init__(self, a: float = 1.0, b: float = 0.0):
        self.a = a
        self.b = b
        self.is_fitted = False

    def fit(self, val_scores: np.ndarray, val_labels: np.ndarray) -> tuple[float, float]:
        """Fit 1D Platt parameters (slope a, intercept b) on validation dataset using NLL loss."""
        eps = 1e-6
        clipped = np.clip(val_scores, eps, 1.0 - eps)
        val_logits = np.log(clipped / (1.0 - clipped))

        def nll_loss(params):
            a_p, b_p = params[0], params[1]
            scaled = a_p * val_logits + b_p
            log_p = -np.log1p(np.exp(-scaled))
            log_1p = -scaled - np.log1p(np.exp(-scaled))
            return -np.mean(val_labels * log_p + (1.0 - val_labels) * log_1p)

        res = minimize(nll_loss, x0=np.array([self.a, self.b]), method="L-BFGS-B")
        self.a, self.b = float(res.x[0]), float(res.x[1])
        self.is_fitted = True
        return self.a, self.b

    def evaluate(self, raw_confidence: float) -> float:
        # 1. Convert raw self-assessed probability p_raw to logit space z = logit(p_raw)
        eps = 1e-6
        p_clipped = max(eps, min(1.0 - eps, raw_confidence))
        z = math.log(p_clipped / (1.0 - p_clipped))

        # 2. Apply fitted Platt scaling: p_calibrated = sigmoid(a * z + b)
        calibrated_logit = self.a * z + self.b
        return 1.0 / (1.0 + math.exp(-calibrated_logit))

Production Challenges & Engineering Lessons

Building this benchmark surfaced several key technical considerations for LLM confidence calibration:

  • SDK and API Schema Nuances: In the modern google-genai SDK, token alternative log probabilities are nested inside response.candidates[0].logprobs_result.top_candidates. Ensuring fallback logic for legacy structures is essential for cross-version compatibility.
  • Handling API Rate Limits (429 RESOURCE_EXHAUSTED): Methods like Self-Consistency (\(N=5\)) and LLM-as-a-Judge hit rate limits under parallel evaluation. I implemented exponential backoff retries directly in _generate_content_with_retry to maintain benchmark stability.
  • Multimodal Ingestion vs CPU Layout Parsing: PyMuPDF layout parsing handles structured text quickly on CPU. However, for complex multi-column resumes or non-standard fonts, direct PDF byte ingestion to Gemini's visual engine eliminates text extraction artifacts.

Architectural Recommendations

Based on empirical benchmark findings, I recommend a tiered production architecture for enterprise document extraction:

  1. Tier 1 Automated Processing (Structured Self-Assessment + Platt Scaling for Gemini 3.0+): For Gemini 3.0+ models, run primary extractions through StructuredSelfAssessmentPlattMethod (or LogProbDeltaMethod + PlattScalingMethod on models supporting logprobs). This delivers optimal calibrated confidence scores in under 5 ms. Extractions with calibrated confidence \(\ge 0.75\) are automatically routed to downstream production systems.
  2. Tier 2 Secondary Verification (Grounding Alignment): Extractions falling below 0.75 are passed to GroundingAlignmentMethod to verify factual claims against raw document text via NLI.
  3. Tier 3 Human-in-the-Loop Audit: Documents that fail Tier 2 verification are flagged as FLAG_FOR_HUMAN_REVIEW, giving recruiters focused, audited queues while automating routine processing safely.
